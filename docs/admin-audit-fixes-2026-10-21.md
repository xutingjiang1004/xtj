## 2026-10-22 IP 识别与发帖属地补充

用户要求继续检查后台用户 IP 和发帖属地，修复城市识别不准的问题并推送。此次改动入口为 [ip-geolocation.js](../render-api/ip-geolocation.js)、[服务器接入](../render-api/server.js)及[后台展示](../js/admin/admin.js)。此节是后续追加状态，不改变上文 2026-10-21 审计时点的记录。

### 已修正的原因

- 原实现只取最快成功的数据源；省级结果会挡住稍慢的城市结果，两个来源冲突也随机采用先到者。现在先收齐有截止时间的国内结果，必要时由既有海外 HTTPS 来源核对，再按国家／省份／城市分别判断一致性。票数打平不选城市，保留有依据的较粗地区；多源一致只表示来源的判断一致，不表示设备的精确物理位置。
- 原实现无条件写 `precision: approximate_city`，省份结果也被标成城市级。现在返回实际层级、城市／省份证据状态、来源 IP、查询时间及最多四条来源判断。后台区分“多源一致”“单一来源推测”“城市待核实”。
- 原缓存有登录六小时及帖子独立二十四小时两层，手动重查仍复用缓存。现在共用规范化 IP 缓存：城市多源一致一小时、单一城市来源十分钟、仅省份五分钟、任何分歧两分钟、失败三十秒。手动重查绕过旧缓存及普通在途请求，旧结果迟到不能重新污染新缓存。
- 修正中国前缀、自治区、区县和运营商尾部的解析；国内来源返回境外国家时不再强行标成中国省份；响应 IP 不匹配则丢弃，省／市行政代码冲突不采用该城市。保留 GBK 解码、HTTPS、请求及正文截止时间，限制响应体和内存缓存。
- 统一 IPv4 映射 IPv6、大小写及带端口 IPv6；可信 Cloudflare 中转不当作用户 IP，无真实客户地址时保留未知，不猜测中转服务器所在城市。仍不接受客户端随意设置的 `cf-connecting-ip`、`x-real-ip` 或帖子 IP 字段作为事实。
- 后台不再从 GPS 或另一次登录的地区补当前 IP。新管理员登录解析失败会清空上一 IP 的地区，普通账号仍通过既有事件／IP 条件核对的 `record_auth_ip_location` RPC 更新，避免旧登录异步覆盖新登录。
