# XTJ 聊天增量交接（2026-09-30）

本次实现阶段 5–7 的主要功能，并补充阶段 8–9 的界面、运行测试和安全检查。底部 Dock 未修改。不能把本文当作所有真机和线上功能已经验收的证明。

## 已实现

- 当前会话／全局消息搜索、日期与类型筛选、服务端游标分页、搜索结果定位；图片、视频、语音、文件、文字链接分类。
- 录音、取消、五分钟限制、音频附件上传和播放；继续复用已有的发送进度、失败状态和重试。支持录音时浏览器语音识别，浏览器不支持时仍能录制并发送音频。
- 服务器异步语音转写：持久化队列、并发租约、服务器重启后的过期租约回收、最多三次尝试、失败重试入口、转写结果同步与搜索。转写仅从已关联的音频注册对象读取，不读取用户提供的 URL；撤回后不转写。
- 回复引用、十五分钟内编辑自己发送的文字消息、六种表情回应、受限文档附件。保留已有撤回、账号级删除、转发、分享、发送状态与重试入口。现有转发仍以文字／附件链接转发，不是复制原媒体对象。
- 归档／取消归档会话，按当前用户保存；共同好友分页查询，隐藏拉黑关系。
- 新上传的私聊附件使用 `dm-private` 私有桶；已授权的聊天 API 返回一小时签名 URL，半小时内复用签名缓存。撤回、取消上传和失败清理使用对象实际所属桶。历史 `uploads` 附件保留兼容。
- 新界面具有移动布局、深色模式、短入场动画及减少动态效果支持。录音切换会话、账号或离开页面会释放麦克风。

## 服务器转写配置

设置 `CHAT_TRANSCRIPTION_API_KEY` 后启用队列。可选：

```text
CHAT_TRANSCRIPTION_URL=https://api.openai.com/v1/audio/transcriptions
CHAT_TRANSCRIPTION_MODEL=whisper-1
```

接口须兼容 multipart `file`／`model` 和 JSON `text` 响应。默认接口的单次转写限制为 24 MiB；更大的音频仍可发送和播放，转写任务会失败。未配置凭据时，音频消息正常工作，“转文字”会明确提示尚未配置。未完成真实提供商调用及线上转写验收。
