# 2026-10-02 帖子板块深入检查与修复

## 检查范围

检查帖子列表、首屏缓存、分页、筛选、点赞、评论、删除、置顶、私密状态、详情及帖子翻译/锐评工具的前端逻辑，并核对既有接口与发布回归。实现修改 `js/core-parts/*`，由构建生成核心脚本和压缩资源。遵守当前产品决定；底部 Dock、发帖工具布局、帖子操作样式与删除玻璃透明度保持原约定。

## 确认并修复的问题

| 场景 | 原问题 | 修复行为 |
| --- | --- | --- |
| 加载多页后重新进入 | 缓存只保存第一页，却保存最后一页的游标，中间帖子被跳过 | 保存首屏范围对应的游标与偏移；旧 v7 缓存从最早缓存帖重建边界，不受置顶排序干扰 |
| 缓存/筛选包含多个显示页 | 服务器已经到末页，直接禁止展开内存中剩余帖子 | 区分服务器耗尽与可见卡片耗尽，哨兵仍可追加尚未展示的内存页 |
| 筛选匹配稀少 | 单轮扫描上限或节流结束时哨兵一直在视口内，不再触发下一次加载 | 提供原生按钮“继续查找帖子”；不清空已有游标、不无上限自动请求 |
| 快速点赞后取消 | 第一次回包的点赞数覆盖了最新的取消意图 | 以回包数量加未发送意图的差值显示，最终与服务器确认结果对齐 |
| 同设备切换账号 | 旧点赞的设备标识可能被当作新账号的点赞，甚至被从本地记录移除 | 有账号归属的点赞按账号识别，已登录按钮状态按用户名查询 |
| 120ms 内连续评论变化 | 合并窗口只丢弃事件，没有尾次刷新，最后一条评论不显示 | 首条立即更新，窗口结束时有变化则再局部刷新一次 |
| 删除评论/不可见帖收到评论 | 全量重建使其他草稿、焦点、媒体与滚动交互丢失 | 删除只更新目标卡片；不在当前 DOM 的帖子不触发全列表重绘 |
| 中文输入法按 Enter | 正在组合文字或 keyCode 229 被当作提交 | 组合输入不提交；普通 Enter 与正常提及选择继续工作 |
| 展开提及后重绘列表 | 文档监听器被移除，但挂在 body 的候选菜单与 ARIA 状态残留 | 同时清理候选、文档监听器和 combobox 展开状态 |
| JSON/流式正文期间切换账号 | HTTP 响应头的认证保护结束后，旧正文仍写入 UI、缓存或触发下一次点赞 | 操作绑定账号和认证代次，在正文读取、认证等待、动画和流读取之后再次检查 |
| 退出或认证失效 | 私密帖内存和详情尚在，空刷新可能继续保留旧界面 | 立即清空帖子、互动、详情及菜单，取消待写缓存与重绘、终止帖子 AI 读取，并使旧分页失效 |
| 新刷新期间旧请求失败 | 旧 catch 回填缓存，旧 finally 解锁新请求 | 仅当前请求代次可恢复缓存、写分页 UI 或释放分页锁；置顶/隐私锁绑定具体操作 |
| 删除响应头成功、正文停住 | 请求计时器在读取正文前已取消 | 超时贯穿正文读取；不确定结果由同身份的删除状态接口确认 |
| 翻译临时失败 | 再次点击只隐藏/显示错误面板，无法重新请求 | 失败后再次点击重新发起翻译 |
