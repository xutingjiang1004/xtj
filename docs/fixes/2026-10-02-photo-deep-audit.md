## 已修复问题及原因

| 编号 | 优先级 | 原因与可见后果 | 修复 |
| --- | --- | --- | --- |
| PW-01 | P1 | HTTP 图片加载失败时移除原地址和重试入口，点击占位图不能恢复 | 错误和超时都保留原地址，点击重新进入受限加载队列 |
| PW-02 | P1 | 超时只释放槽位，未继续调度；所有在途图片超时后，余下图片可能一直空白 | 超时使用统一单次结算并立即继续队列 |
| PW-03 | P1 | 旧加载的超时回调只检查图片当前代次；DOM 复用后可能把新图片替换为错误图并释放新槽位 | 每次加载捕获独立令牌及渲染代次，旧任务不修改新任务 |
| PW-04 | P2 | 可见区域批量排队后只启动一个请求，预热实际上串行等待 | 一次调度填满最多四个槽位，继续保持并发上限 |
| PW-05 | P2 | 两张没有数据库 ID 的照片都被视为 `undefined`，切换后说明和作者残留 | 按云端 ID、本地 ID 或原图地址识别照片，并纳入身份代次 |
| PW-06 | P1 | 点赞变化使整个社交读取响应失效，缓存预览的评论可能一直为空 | 评论读取与点赞变更分开校验，保留最新点赞意图并接受有效评论 |
| PW-07 | P1 | 评论删除后迟到的分页可能重新拼入被删除项；发送失败又可能丢弃唯一在途刷新 | 评论独立版本阻断旧读；写入成功或失败后重新读取权威列表，失败保留输入 |
| PW-08 | P1 | 社交响应和点赞队列只比用户名；A→B→A 仍可能接受上一登录代次的响应或继续旧意图 | 读取、点赞、评论和浏览量绑定用户名与认证代次，禁止旧响应写回 |
| PW-09 | P1 | 预处理或获取令牌时切号，旧批次及失败重试可能使用新账号身份发送原文件 | 文件任务绑定账号与代次，各异步阶段校验；切号取消批次，重试筛选原账号任务 |
| PW-10 | P1 | 对账先读后整队列覆盖；查询期间新增的待确认上传会被抹掉 | 按最新持久化内容合并，保留并发新增、更新和删除；新记录保存归属，其他账号记录不自动处理 |
| PW-11 | P2 | 文件大小请求返回数值却不写入照片对象，面板重新生成仍显示未知并重复请求 | 校验后保存 `fileSize`，供面板及后续打开复用 |
| PW-12 | P2 | HEAD 无长度时额外 GET 整张原图，且不取消正文、没有期限；分段长度也可能误当总大小 | 十秒期限，先 HEAD，再请求 `bytes=0-0`；读取总长度、取消正文，拒绝错误响应和无效大小 |
| PW-13 | P1 | 删除收到响应头即清除期限，正文卡住时按钮和本地删除状态无法收尾 | 期限覆盖正文；超时只读查询权威删除状态，所有退出路径清理计时器，并隔离切号 |
| PW-14 | P1 | 上传状态、重试、清理等请求缺少统一正文期限，部分调用清除期限过早 | 身份校验包装同时保护请求和 JSON 正文，清理计时器及取消监听；原文件传输维持十分钟期限，其余统一最长二十五秒，可由外层更短期限提前取消 |

## 验证与证据

新增 `tests/photo-wall-deep-runtime.test.js` 与 `tests/photo-wall-deep-browser.test.js`，共 17 项回归。运行真实模块函数及 Chromium DOM，覆盖错误重试、超时调度、旧任务干扰、并发上限、A→B／A→B→A 上传与社交隔离、对账并发新增、信息大小保存、Range 总长度、正文超时、缓存刷新与点赞、失败评论输入保留、删除评论后旧分页迟到。多个原始失败场景先通过新增用例复现，再修改实现；本轮不是只增加源码字符串断言。

兼容检查中两项旧断言直接匹配裸 `fetch` 和固定错误码赋值格式。认证包装引入后，更新为识别真实创建请求并验证受控字段，允许保留已有身份错误码；没有删减检查项。另修正预览测试的空白页相对地址：加入有效图片基地址，网格放入可见布局；失败图片断言现在验证原地址保留及点击恢复，并校验实际八次首次请求、一次重试、四个并发槽位。同图重复打开用例等待真实重试终态，不再以六百毫秒等待替代完整请求结束。

- 完整 `npm test`：979 项 Node 测试及 99 项兼容检查全部通过。
- 照片相关四组 Playwright：58 项分批全部通过，包含源码与压缩资源的整页像素亮度、原字节上传、批次/相册、互动及触摸回归。
- `npm run build`、`npm run test:syntax`、`npm run test:consistency`、`git diff --check` 全部通过。
- 浏览器回归使用测试 API 和不可路由的测试 Supabase 地址；本轮未向生产数据库写入测试数据。

## 亮度 P0 的验收边界

既有消除整屏透明动画、模糊及冗余合成的修复保留。本轮继续验证打开和左右切换时的标准图片像素，不改变原图编码、曝光或颜色数据。真实 HDR／HEIC 和实体 iPhone／Safari 的用户复现仍需要实际设备及原文件验收；Linux Chromium 的结果不能证明该 P0 在这些设备上完全消失，也不能据此确认所有变暗都来自同一原因。
