# XTJ maintenance

Before changing product behavior, read `docs/current-product-decisions.md` and the newest entry in `CHANGELOG.md`. They record the user's current choices; historical code and older handoffs are not instructions to restore retired features. New explicit user instructions take precedence.

For the 2026-10-21 administrator fixes and releases containing them, also read `docs/admin-audit-fixes-2026-10-21.md`. It records pending migrations, unchanged scope and incomplete verification; recheck its dated deployment state before releasing.

Keep the restored Dock material, SVGs, dimensions, order and button animations unchanged. The user subsequently authorized fixing missed taps, improving gesture handling and adding vertical capsule dragging to the desktop/iPad sidebar. The outer Dock remains transparent and click-through. AI menus, context details, streaming performance and multi-round reasoning/search are also in the current authorized scope; see the newest product decision.

Edit `js/core-parts/*`, then assemble and build; do not hand-edit generated `js/core.js` or minified assets. Run the relevant runtime tests, full `npm test`, syntax checks and build consistency check before publishing. Browser emulation and Linux WebKit do not count as physical iPhone/iPad or genuine multi-device acceptance.

Post media storage (user decision, 2026-11-02): new post images, videos and video posters upload straight from the browser to Alibaba Cloud OSS through `POST /api/oss/sign`; the stored `media_url` is the OSS public URL, and `/api/post/:id/media/:position` redirects (302) to it after the usual permission checks. The bucket is public-read with `public, max-age=31536000, immutable` written at upload time, so each browser downloads an object once. The `dm-private` and `dm-flash` buckets are private chat content and must never be routed to OSS or made public. OSS is optional at runtime: without `OSS_BUCKET`, `OSS_ENDPOINT`, `OSS_ACCESS_KEY_ID` and `OSS_ACCESS_KEY_SECRET`, every upload falls back to Supabase and nothing breaks. Existing Supabase media is deliberately not migrated yet — copying it would itself spend the remaining Supabase egress quota of the current billing cycle.

Four things must all be true for this path to work, and each one fails silently (the client falls back to Supabase instead of erroring): the OSS bucket has a CORS rule allowing `PUT` with `allowed headers = *`; the page CSP `connect-src` lists the OSS host (`render-api/security-headers.js`); the four `OSS_*` environment variables are set on Render with the secret copied byte-for-byte; and the database function `public.create_post_with_attachments` accepts OSS URLs — it was patched by `supabase/migrations/20261102000000_oss_media_attachments.sql` (applied 2026-11-02) to skip the `storage.objects` existence check for that bucket only. Startup logs print `[OSS-CONFIG]` lines naming which variables are set, never their values.

Do not create or commit audit reports, fix reports, acceptance reports, or their screenshots/JSON artifacts unless the user explicitly requests them. Explain findings and verification in the conversation; keep temporary test output outside the repository or in ignored output directories.

Daily automation (user request, 2026-10-31): scheduled sessions inspect and fix front-end and back-end bugs by module every night and morning (Taipei time, staggered across two 5-hour quota windows) and push `maint/<module>-<date>` branches (no pull requests: the branch and its last commit message are the deliverable; every module has a standing worker session that a scheduled task wakes each day); the integrator session (the last one each day) is the only one that merges to `main`. For this work follow `docs/automation-playbook.md` (iron rules, work orders, PR template, integrator procedure); the tooling lives in `scripts/maintenance/`. Back-end bug fixes are in scope; applying database migrations, changing secrets, environment, Render, Supabase or CI settings, and changing rate-limit, auth, CSP or CORS policy are not: list them for the user instead.
