## 一、P1 优先处理

### P1-1 行为遥测默认无同意门控，与合规声明冲突（源码确认）

- **位置**：`js/login-device.js:839-871, 1000-1088, 1116-1164`；后端 `render-api/server.js:16830-16859`；声明 `DATA_COLLECTION_COMPLIANCE.js:61-63, 79-91`。
- **证据**：页面初始化直接注册点击、焦点、切换、滚动、页面可见度、Web Vitals 和 session summary 监听；`restorePendingBehavior()`、`initSafeAnalytics()` 无条件执行。已登录时队列通过认证 token 发到 `/api/user/behavior`，服务端将事件与 `req.userName` 关联存储。声明却把行为追踪列为 OFF，并规定逐用户行为需用户同意。
- **边界**：载荷对 metadata 有 sanitize/限长；没有证据表明会上报输入框正文。明确问题是逐用户事件记录默认启动，且 `getMeaningfulTarget()` 可能记录按钮文字、placeholder 等目标描述。
- **影响/修复**：隐私预期与实际行为不一致；初始化/恢复/上报均应受真实可撤销 opt-in 控制，默认不采集；删除未经同意的本地待发队列，并对现存历史数据设置清理策略。另需统一隐私声明和实际开关。

### P1-2 精确定位写接口仅鉴权，不验证单次用户授权或留存期限（需产品/隐私政策决策）

- **位置**：`render-api/server.js:16379-16437, 16465-16501`；管理员读取路径约 `16625-16737`。
- **证据**：API 可接收并保存精确坐标/历史记录，管理员端可读取；后端代码没有把本次明确授权状态作为该条数据写入条件，也未见坐标 TTL/自动过期。
- **触发/影响**：带有效用户 token 的调用方可以直接调用 API，不必从网页定位控件发起；路由注释或前端浏览器权限不等于应用层对本次上传的同意记录。属于高敏感个人数据范围，不是匿名读取漏洞。
- **修复建议**：把显式 opt-in/授权时点与写入绑定；采用最短留存、用户撤销/删除、访问审计；没有必要时降精度。需先由产品/合规确认保留目的与期限。

### P1-3 自定义模型 SSRF 防护使用错误的 fetch Agent 参数，DNS pin 可能不生效（运行时/出网策略需验证）

- **位置**：`render-api/server.js:20700-20715, 20868-20879, 21227-21263`；provider 测试 `render-api/provider-registry.js:485-535`。
- **证据**：先调用 `assertSafeWebUrl()` 并创建 pinned Agent，后用 Node 全局 `fetch()` 并传 `{ agent: pinnedAgent }`。内置 Node fetch/Undici 使用 `dispatcher`，而非传统 `https.Agent` 的 `agent` 选项；代码不能证明连接实际复用了已校验 DNS 地址。当前 SSRF 校验、标准 HTTPS 端口、拒绝重定向仍有作用，但 DNS rebinding 的 TOCTOU 防线可能失效。
- **触发/影响**：已登录用户提供可控自定义 base URL，域名 DNS 在校验与连接时返回不同地址；风险等级 P1，实际可利用性还取决于 Node 实际 fetch 实现、网络出口 ACL 和 DNS 条件。
- **修复建议**：改用 Undici `dispatcher`/固定 lookup，或使用与 `web-fetch.js` 相同的 pinned https 请求实现；继续禁止跳转；用可控 DNS 重绑定集成测试验证“实际连接 IP”，不能只测 URL 校验。

### P1-4 Code 工作台将仓库文件内容交给模型且缺敏感文件默认排除/用户确认

- **位置**：`js/code-workbench.js:59-61, 2203-2290, 2526-2564`。
- **证据**：文件树过滤覆盖依赖/构建目录和锁文件，但没有通用 `.env`、私钥、credential 等敏感文件拒绝策略；点名读取、整库读取和模型 `read_file` 工具可以将选中文件内容加入模型上下文。system prompt 的“禁止复述/保护密钥”不是访问控制。
- **影响**：用户授权的 GitHub Token 有权读取的敏感文件可被发送给内置或用户配置的第三方模型；恶意仓库文本可能影响模型后续工具决策。未证明模型一定泄密，但数据外发面源码可确认。
- **修复建议**：默认排除敏感路径并做内容型 secret 检测；敏感文件读取/发送需逐次明确确认；第三方模型页面清楚说明数据接收方；将仓库文件隔离为不可信资料，并限制工具可读取范围。

### P1-5 高权限 MCP 管理操作的 confirm 参数由同一工具调用者提供

- **位置**：`mcp-servers/xtj-admin/server.js:200-219, 273-285, 386-404`。
- **证据**：删除账号/帖子、举报处置、封禁等参数中的 `confirm`、`confirm_permanent` 是普通工具参数；调用方传 true 即通过工具层确认。
- **前提**：MCP Server 已用管理员 token 登录，且可被不可信或受 prompt injection 影响的 agent 调用。若 MCP 仅连接可信人工客户端，风险下降。
- **影响/修复**：工具参数不等价于独立人工确认；对破坏性操作改成宿主层/独立审批确认、短期最小权限 token，并将全部写操作记入持久化管理员审计。

### P1-6 账号删除流程可能遗漏按用户名关联的数据及作为收件方的 DM（隐私删除完整性）

- **位置**：`render-api/server.js:15118-15147, 15217-15282, 15301-15319`；相关表迁移 `041`, `043`, `018`, `029`；DM 查询 `14255-14289`。
- **证据**：删除用户流程清理 `posts/likes/comments` 等有限实体；未见逐一清理会员额度、使用事件、邀请码兑换、AI 站内数据、代码索引等用户键记录。DM 记录以发送者存 `user_name`、收件人存另一字段；按被删用户名仅删 `user_name` 不会自动删除其他人发给该账号的消息。
- **影响**：若产品承诺账号删除即清除/匿名化个人信息，数据库可能继续关联用户名并可由对话参与者访问历史消息。不是所有留存都必然违法，需先定留存政策。
- **修复建议**：建立统一、幂等、可续跑的删除/匿名化计划，覆盖全部用户键与 DM 收发双方、Storage 和索引；每个删除步骤检查 error/行数并产生日志。明确法定/业务保留例外。

### P1-7 管理员 MCP API 基址不校验 HTTPS/host，Bearer token 发往配置目标

- **位置**：`mcp-servers/xtj-admin/server.js:26-29, 41-50`。
- **证据**：`XTJ_API_BASE` 仅检查非空；apiRequest 拼接任意配置 URL，并在有 token 时设置 Authorization Bearer header。
- **触发/影响**：部署误配/被污染为 HTTP 或攻击者控制主机时，管理员 token 可发往非预期端点。
- **修复建议**：启动解析 URL；生产强制 HTTPS、禁止凭据/异常端口并配置 host allowlist；校验每个请求解析出的最终 origin。

### P1-8 Code 工作台连续输出中断时可能把不完整回答当作成功

- **位置**：`js/code-workbench.js:608-650`。
- **证据**：parser 只按 `\n\n` 分帧；标准 CRLF 分隔符 `\r\n\r\n` 不匹配。EOF 时重复处理 buffer，但未强制 flush 未闭合最后帧；没有 `done` 的情况下仍 `finish(true, fullText)`。
- **影响**：代理采用 CRLF 或连接中途结束，可能丢最后事件或将半截代码作为完整 AI 输出，工作台可能展示可应用的不完整文件。
- **修复建议**：统一共享 SSE reader；兼容 LF/CRLF、跨 chunk 和 EOF flush；未收到终态事件时返回 interrupted，不允许以成功态提供“应用/提交”。

### P1-9 搜索配额并发检查与实际搜索之间存在超发窗口（每进程/跨实例）

- **位置**：`render-api/server.js:1738-1745, 1778-1785, 8266-8273`；跨请求 token quota `render-api/ai-quota.js:160-165, 254-289, 292-337`；DB 截断 `054_quota_and_check_fixes.sql:63-88`。
- **证据**：同一轮工具调用用 `Promise.all`；搜索分支先 `measureSearchQuota()` await，随后才更新请求级 `searchConsumed` 并发上游。多个并行调用可能读取相同剩余额度。请求之间的 chat token 门禁与完成后记账也是两次 RPC；数据库消费 RPC 会把账面消费截断到剩余额度，但已经生成的上游响应无法撤销。
- **影响**：可能超过配额调用第三方搜索/模型并产生成本；本地每请求计数无法实现跨请求/跨实例预留。
- **修复建议**：数据库原子预占额度/搜索次数，完成后按实际结算或失败释放；同请求搜索调用可串行化；添加多个并行搜索、并发 chat 边界测试。

### P1-10 审计/登出 token 撤销写入忽略 Supabase 返回的 error

- **位置**：`render-api/server.js:10947-10960`。
- **证据**：`persistRevokedToken()` await `supabase.from(...).insert()` 但不检查返回对象的 `{ error }`；常见 SDK 数据错误以返回值呈现，不会进入 catch；之后仍将哈希加入当前进程内存并返回 true。
- **影响**：DB 插入失败时当前实例会暂时拒绝 token，但换实例/重启后撤销状态丢失，接口可能错误报告成功。管理员签名 token 可由签名/过期规则验证，需确认其他机制。
- **修复建议**：检查 insert error/返回行后才成功；失败返回 503 并保留客户端可重试状态；最好使用独立撤销表、唯一键及稳定会话版本机制。

### P1-11 远程 DOCX/XLSX/PDF/ZIP 下载字节限制不约束解压后资源

- **位置**：`render-api/server.js:1433, 2112-2150, 2815-2825, 2843-2849`；`render-api/file-parsers.js:26-35, 61-83`。
- **证据**：下载大小有限制，但 `read_document` 直接调用文档解析器；`read_zip` 调 JSZip 后将 entry 完整解压成字符串，之后才做文本截断。后置截断无法限制前面的 CPU/内存消耗。独立 PDF 解析模块的保护路径没有被 `read_document` 使用；即使 Promise timeout 也不能中断同步解析阶段。
- **影响**：公开压缩炸弹/复杂文档可造成高内存、CPU 或 event-loop 阻塞；重复请求可能造成服务不可用。
- **修复建议**：预估/约束展开总字节、entry 数、压缩比、页数/行数；读取流时累计限额；将重解析放可终止 worker/独立进程，超限即中止。

### P1-12 GitHub 浏览量 RPC 允许 anon 直接增加任意帖子计数

- **位置**：`supabase/migrations/056_fix_increment_post_views_scope.sql:31-56`。
- **证据**：`SECURITY DEFINER increment_post_views(UUID)` 按 id 更新所有非系统 marker 帖子，不检查 visibility；给 `anon, authenticated, service_role` 授 EXECUTE。服务端 `/api/post/view` 另做鉴权/去重，但不能限制调用公开 Supabase RPC 的 anon。
- **影响**：知道帖子 UUID 的任意持 anon key 客户端可绕过后端逻辑反复刷 views；私密帖的精确 views 也会从 RPC 返回值泄露。匿名前端当前是否直接调用该 RPC需再查运行调用点，但 grant 让直接调用本身成立。
- **修复建议**：撤销 `anon` 对 SECURITY DEFINER RPC 的权限，改走后端；或在函数内部校验帖公开状态、限速/幂等，并避免返回私密帖计数。

### P1-13 057 隐私数据清理迁移可能遗留异常或嵌套格式的敏感值

- **位置**：`supabase/migrations/057_remove_consented_collection.sql:47-76`。
- **证据**：对 JSON parse 失败的旧记录打印 NOTICE 后 continue；仅处理顶层 object 键，非 object 跳过；迁移报“已清除”行数而没有最后 residual scan。
- **影响**：运行迁移不等于能保证所有历史敏感字段物理清除。线上是否存在异常/嵌套值、迁移是否运行，仓库不能证明。
- **修复建议**：运行后输出并核实残留行/键数；异常行明确隔离/删除/人工复核；如支持嵌套格式，递归移除敏感 key；部署清单加入 migration 057 的执行与验收。

### P1-14 从全新迁移快照回放时 likes/comments.post_id 类型疑似阻塞（部署条件项）

## 二、P2 可靠性、功能、性能和中风险

### P2-1 个人活动查询的账号切换竞态可能把旧账号响应写进新账号共享状态

- **位置**：`js/core-parts/03-profile-report-ai.js:622-637, 995-1031, 1032-1062, 1073-1123`。
- **证据**：同一个 `profileActivityState.loading` 跨账号共用；请求启动时用 `currentUser` 查询，但异步完成写 `loadedUser = currentUser`（响应时当前值），没有捕获请求用户名/代次或 abort。快速切号后旧请求可污染共享点赞/评论/帖子状态并被标记成新账号缓存。
- **注意**：当前函数会在无 currentUser 时清空，但没有证据说明所有切号路径都在旧请求完成前调用该清理；竞态成立依赖请求未完成期间切号且新页未阻止旧响应。
- **修复建议**：捕获用户名和 generation；响应写状态前比对当前身份；切号/登出递增 generation 并重置 loading/cache。

### P2-2 桌面聊天双击刷新对同步函数返回值调用 `.catch()`，触发 TypeError

- **位置**：`js/desktop-shell.js:80-86, 88-170, 216-227, 273-280`。
- **证据**：`syncChatBadge`、`syncContacts` 均为同步函数无 Promise 返回；刷新分支直接 `window.syncContacts().catch()` / `syncChatBadge().catch()`。双击当前桌面聊天导航会在 `.catch` 上抛异常并中断该路径。
- **修复建议**：同步调用不链 catch，或用 `Promise.resolve().then(fn)` 统一捕获；补刷新行为测试。

### P2-3 768–1279px 布局隐藏唯一统计卡片

- **位置**：`index.html:298-305`；`css/ui-shell.css:1980-2031`。
- **证据**：`#statsSection` 位于 `.desktop-right-rail` 的 overview card 内；平板断点隐藏整个 rail，代码中未找到该卡片的第二份副本。
- **触发/影响**：宽 768–1279px、高度满足断点的视口中，统计入口随 rail 隐藏。
- **修复建议**：布局重排确保统计卡保留；对 767/768/1279/1280 宽度和横竖屏做视觉回归。

### P2-4 管理后台 `loadAllData` 超时解锁但不取消/隔离旧请求，旧结果可覆盖新数据

- **位置**：`js/admin/admin.js:892-967`（具体触发 897-953）。
- **证据**：超时安全阀释放共享 promise/锁，却没有 abort 或请求代次校验；旧请求返回时仍能写共享帖子/互动/用户数据。之后新请求也可能同时在飞。
- **修复建议**：AbortController + 请求 generation；仅当前代次允许 commit state；超时 UI 保留错误/重试状态。

### P2-5 举报列表失败被转成空列表，可能误显示“暂无举报”

- **位置**：`js/admin/admin.js:2724-2732, 2839-2851`。
- **证据**：`loadReportsData` catch 将 `reportsData=[]`，渲染者可能显示空列表，而非明确失败；轮询会影响徽标/状态。
- **修复建议**：保留上次成功数据，分离 `loading/error/data` 状态；成功返回空才展示空状态。

### P2-6 私信消息数固定限 180 且缺少加载更早历史入口

- **位置**：`js/core-parts/06-chat-and-nav.js:1044-1053`。
- **证据**：请求固定 `limit=180` 并把该结果当当前会话列表渲染，相关路径未见游标续载。
- **影响/修复**：长对话旧消息不可达；实现稳定游标、加载更早并维持滚动锚点。

### P2-7 管理端互动列表固定只显示最多 500 条，没有翻页或服务端搜索

- **位置**：`js/admin/admin.js:907-918, 1633-1665, 2700-2721`。
- **影响**：评论/点赞超 500 后管理员不能在当前页面访问更旧记录；全量 `/admin/data` 数据传输随数据量扩大。
- **修复建议**：服务端条件查询 + cursor 分页，管理员搜索/导出要有审计及限制。

### P2-8 Code 工作台 AI 流式增量每次重渲染累计全文，长代码可能卡顿

- **位置**：`js/code-workbench.js:2449-2454, 2513-2518, 2598-2603`。
- **证据**：每个内容片段将完整累计全文传 Markdown renderer 并替换 HTML；处理量随回复增长重复扩大。
- **修复建议**：按 animation frame 合并更新，采用增量 patch 或完成态再渲染，并压测长文件。

### P2-9 账号注销/数据清理范围没有迁移/测试端到端闭环

除 P1-6 之外，当前 `npm test` 大多是源码契约测试；没有连接隔离数据库检验“删除用户后所有引用消失”。这是验证缺口，不等于生产已留存数据，建议跟 P1-6 同批测试。

### P2-10 Storage 删除部分成功时可能把清理队列标 completed

- **位置**：`render-api/server.js:12818-12839`、照片删除流程约 `12896-12915`；共享实现 `render-api/storage-cleanup.js:166-215`。
- **证据**：两处直接 `remove(paths)` 后以 `removal.error` 是否为空决定 completed，未确认返回数据中每条对象是否都删除；共享 cleanup helper 有逐路径核对/重入队逻辑。
- **前提**：Storage SDK 对批量部分删除以成功 data + 未删除路径返回（无整体 error）。需通过 SDK 合约/模拟确认部署版本语义。
- **修复建议**：统一走共享 `removeStorageWithQueue()` 或逐路径核对，未确认路径保留重试。


### P2-11 头像并发更新可能清掉另一请求刚插入的头像记录/文件

- **位置**：`render-api/server.js:14132-14169`。
- **证据/触发**：头像上传插入后再查询并清理“其他”头像记录；同一账号两个更新交错时，较早请求的清理查询可能包含较晚请求插入行。
- **修复建议**：事务/每用户串行锁；只清除不再是 current avatar 的旧路径，并按引用状态确认后删除。

### P2-12 照片大请求在内存 body 解码前才消费字节配额

- **位置**：`render-api/server.js:12314-12340, 12381-12398`。
- **证据**：`express.raw` 允许约 55MB 请求；后续才检查 50MB并调用 Sharp；500MB/小时用户配额在处理之后。无对应 per-user 并发解码上限。
- **影响/修复**：多个并发大请求可令内存峰值远超用户小时配额的直觉限制；应加并发闸、流式接收/反压、像素与解码预算。

### P2-13 DM 媒体 URL 用 `uploads` bucket `getPublicUrl`，可能绕过对话成员访问控制（需验证 bucket policy）

- **位置**：`render-api/server.js:14568-14576`；客户端上传 `js/core-parts/06-chat-and-nav.js:1193-1215`；DM registry 只限制 `chat/` 路径 `render-api/dm-media.js:16-20`。
- **事实与边界**：应用把附件地址生成为公开 URL。是否可匿名下载由生产 Supabase `uploads` bucket 的 public 状态/RLS/Storage policy 决定，仓库没有发现对应 bucket policy SQL，线上未核验。若 bucket public，取得 URL 即可绕过 DM 会话检查；若 private，`getPublicUrl` 不足以证明能访问，但实现仍应使用签名 URL/后端授权读取。
- **修复建议**：核验生产 bucket；私信附件使用独立 private bucket，读取按参与者鉴权后签短时 URL。

### P2-14 DM 请求结果不确定时前端清理可能与服务端补偿重复竞争（需要客户端代码/动态复核）

- **位置**：发送客户端 `js/core-parts/06-chat-and-nav.js:1252-1285`；后端 `render-api/server.js:14689-14711` 已在未知提交状态时按 actor_key reconcile 并负责 cleanup。
- **复核结果**：后端已经实现提交结果对账和持久化清理队列，不能简单称“必然删除已提交附件”。当前仍要核对前端在请求超时/失败响应时是否自行直接 delete 并绕过 reconciliation。此点作为待动态验证，不升为已确认漏洞。

### P2-15 登录设备基础事件与用户可选设备采集设置语义不清

- **位置**：`render-api/server.js:16956-17129`、公开设置 `/admin` 读接口约 `17160-17185`。
- **证据**：`record_device` 关闭只令 `finalDeviceMeta=null`，登录事件仍保存 IP/UA/基础请求元数据。后端源码同时体现有些字段作为安全日志基础记录、有些作为可选 fingerprint。
- **边界**：与其宣称“设置关闭后设备相关字段全停”，这可能是“基础安全日志 vs 可选设备画像”语义没有拆分/说明；需要对照隐私声明和管理员 UI，不能直接定为无同意采集漏洞。
- **修复建议**：拆分“短留存必要安全日志”和“可选设备画像”字段/开关，明确管理员界面/用户说明与 TTL。

### P2-16 默认管理员用户名 `xxz` 及 Render 公开配置硬编码（条件性）

- **位置**：`render-api/server.js:169-175`；`render.yaml:80-81`。
- **证据**：服务端缺 env 时 fallback 到 `xxz`；仓库 Render blueprint 本身也给 `ADMIN_USERNAME: xxz`。登录仍需 ADMIN_PASSWORD；报告已有 2026-08-05 强制 env 曾导致生产站停机的说明，不建议未经发布预案直接把进程改成缺值退出。
- **影响/修复**：用户名是公开/预测值且承担管理员身份标识；降低身份信息强度、与 token type/密码判定合并扩大后果。应安全迁移到部署密钥并审查管理员授权链；不能只“改成启动崩溃”。

### P2-17 多实例限流/上传字节配额由进程内 Map 维护

- **位置**：`render-api/server.js:4482-4515, 5987-6015, 12314-12332`。
- **证据**：普通 IP/path rate limit、照片上传用户字节窗口用本地 Map；另外有持久化 `securityRateLimit()` 用于敏感端点，不能因此说所有限流都单机。
- **影响/修复**：在多个 Render 实例/进程下配额按实例倍增，重启重置；迁移共享原子 RPC/Redis 或明确部署只有单实例且加实例扩展防护。

### P2-18 MCP 图片批量处理缺资源上限，输出路径符号链接写越界（本地工具威胁模型）

- **位置**：`mcp-servers/xtj-image/server.js:21-32, 67-81, 88-100, 103-134, 136-164`。
- **证据**：输入用 `realpath` 限制根目录，但产物路径仅拼接后直接 Sharp `toFile()`；未拒绝已有 symlink 输出。批量操作 `readdirSync` 后处理所有匹配文件，不逐文件调用 `validateFile()`；缩略图 sizes 没有个数/width 上限。
- **前提**：MCP 执行账户的 SOURCE_DIR 中有攻击者可放入 symlink/大量或超大图片的能力；这是本机工具边界，不是公网接口漏洞。
- **修复建议**：输出目标拒绝 symlink、原子安全新建；批量逐文件校验并限制数量/累计字节/像素/耗时。

### P2-19 MCP 邮件允许任意 HTML（受调用者/收件人策略影响）

- **位置**：`mcp-servers/xtj-email/server.js:32-46, 76-83`。
- **证据**：通用 `send_email` 对用户提供的 html 直接发信；不同于模板告警路径，没有 sanitize。域名/地址白名单可限制接收方；没有白名单时默认仅 ADMIN_EMAIL。
- **影响/修复**：若调用者被提示注入控制，可能向允许范围发送仿冒/追踪邮件。普通邮件用纯文本/固定模板，对不可信字段 contextual escape。
- **注意**：收件人 `*` 是显式配置才启用的全放行，不是默认行为；生产应拒绝意外 wildcard。

### P2-20 Code 工作台 GitHub Token `sessionStorage` 不是账号隔离存储

- **位置**：`js/code-workbench.js:223-233, 240-258, 274-288`。
- **证据**：仓库信息走当前用户作用域 localStorage，但 Token 优先读取固定键 `xtj_code_token` 的 `sessionStorage`；切换 XTJ 用户登录不改变该键。
- **触发/影响**：同一标签页先后用多个 XTJ 账号，后一个账号工作台可能仍读取前一个账号的 GitHub Token。Token 刷新可保留在当前 tab，账号身份切换时若未清理则会串用。
- **修复建议**：Token session 键也按规范化用户 scope 隔离；账号切换、登出清理内存状态，并要求重新授权。

### P2-21 工作台“记住 Token”文案和实际存储生命周期不一致

- **位置**：`js/code-workbench.js:9-13, 223-233, 282-288, 708-716, 1179`。
- **证据**：保存只进 sessionStorage，连接 UI 的“记住 Token”控制不影响 saveToken 存储方式。
- **修复建议**：明确只当前标签页，或由复选框切换持久策略；默认 sessionStorage 更安全。

### P2-22 部分管理交互不满足键盘/屏幕阅读器操作

- **位置**：`index.html:302-305, 498-505`；`admin.html:17-25, 36-45, 53-72`；`js/admin/admin.js:2881-2930`；`js/core-parts/04-posts-interactions.js:4080-4092, 4145-4159`。
- **证据**：`onclick` 的 div 没有 button 语义；后台 tabs 缺 `tablist/tab/aria-selected/aria-controls`；登录输入仅 placeholder；动态 dialog 缺焦点管理；重试 role=button 只处理 click 未处理 Enter/Space。
- **修复建议**：原生 button/label、完整 tab/dialog 焦点交互、键盘重试处理，配合 axe/Playwright 键盘测试。

### P2-23 登录 UI 缺请求超时；后台加载状态恢复/陈旧响应处理不一致

- **位置**：`js/admin/admin.js:751-817`（登录 fetch 无 timeout）；`892-967`（数据加载竞态见 P2-4）。
- **影响/修复**：慢连接可让登录按钮保持禁用；统一 AbortController/timeout 与 finally 恢复状态。

### P2-24 迁移执行与验收仅手动提示，合规清除 migration 057 没列在 README 部署清单

- **位置**：`README.md:116-124`（说明 migration 手动执行）；部署注意事项约 `281-282` 只突出 052；`supabase/migrations/057_remove_consented_collection.sql`。
- **边界**：不能据文档断言线上没执行；这是变更执行证据/验收缺口。
- **修复建议**：发布迁移清单列所有未执行编号、顺序、不可逆数据清理及验收 SQL；记录生产 migration ledger/结果。

### P2-25 CI 没有依赖安全扫描，lockfile 有 HTTP tarball

- **位置**：`.github/workflows/ci.yml:28-41`；`package-lock.json` 早期行中有 `http://mirrors.tencent.com/...` resolved。
- **边界**：lockfile 的 integrity hash 减少静默篡改风险；没有证据表示当前依赖已含可利用漏洞。
- **修复建议**：将 tarball URL 换 HTTPS 官方/可信镜像；CI 加 npm audit 或 SCA，并设置可解释的严重度门槛。

### P2-26 全量自动化测试不稳定依赖公网 DNS/外站可达

- **位置**：`tests/web-fetch-lookup.test.js:144-156`；`package.json` 的 npm test 将其纳入。
- **证据**：两项端到端用例直接访问 `https://example.com`、`https://www.baidu.com`；不注入可控公网 DNS/transport。当前环境实跑两项均报“网页主机解析到禁止访问的内网地址”，内网阻断用例通过。
- **影响**：VPN、DNS 污染、受限 CI 出网会让完整测试失败，无法区分服务故障与 SSRF 防线对解析目标的正确拒绝。
- **修复建议**：日常测试注入 mock DNS/transport 做确定性安全边界验证；外网 smoke 独立标为 opt-in/网络 job，并核验解析 IP、不要关闭内网保护。

### P2-27 Render Node 版本约束源不一致

- **位置**：根 `package.json:29-31` 要求 Node >=22；`render-api/package.json:5-7` 声明 >=20.6；CI `.github/workflows/ci.yml` 使用 Node 22。
- **边界**：Render blueprint 当前在根目录执行构建/启动，所以由根包约束主导；若有人把 `render-api` 独立部署/安装会得到不同要求。
- **修复建议**：统一版本声明并设置 `.nvmrc`/Render/CI 同版本，避免不同运行入口不一致。

### P2-28 CSP 的 `unsafe-inline` 仍显著削弱 XSS 纵深防御

- **位置**：`render-api/security-headers.js:19-24, 38-40`。
- **证据**：script-src、style-src 保留 `unsafe-inline`，源文件明确承认 inline script/on* 属性规模很大、nonce 工程尚未完成。
- **影响**：发生 HTML/DOM 注入时 CSP 缓解力低；不是独立 XSS 漏洞，前置是其他注入点。
- **修复建议**：分批替换 inline event 与 script，统一 nonce/hash，启 report-only CSP 后逐步 enforcing。

### P2-29 平板 overview 卡/资料加载、桌面错误与状态一致性问题

前述 P2-1 至 P2-7 是已源核实项；本次没有浏览器实测，不把 agent 只凭静态 CSS 的视觉推断扩成更多断言。建议下次修复阶段配合 Playwright 断点截图、切号竞态和桌面聊天刷新复现。

### P2-30 取消深研/自定义模型连接关闭后部分上游任务可能继续

- **位置**：`render-api/server.js:20631-20652, 20719-20721, 20868-20925`；深研 `21201-21202, 21238-21263, 21384-21423`。
- **证据**：自定义流断开回调设置 `aborted = true`、清 heartbeat，但 controller 仅通过超时 abort；深研 worker 按 Promise.all 并行，断连没有可靠传播到每个上游/搜索 reader。
- **影响**：客户端离线后请求可能继续占资源并产生上游成本。
- **修复建议**：close/aborted 触发 AbortController；把 signal 传入 fetch、搜索 provider、工具与 worker；取消 reader/Promise 并做一次性记账。

### P2-31 断连记账路径可能估算记账并在流程收尾再次记账（需逐个分支动态确认）

- **位置**：`render-api/server.js:19701-19729` 与约 `19946-19967`，`recordAbortedStreamUsage()` 约 `3834-3874`。
- **证据**：断连监听器会在 `message` 存在时按 `usage:null` 立即估算写账；另有流程完成后的真实 usage 补记入口。静态存在双路径；是否在同一请求两者都到达需按 `aborted`/幂等条件作行为测试，不能仅由双调用点推断每次必然双扣。
- **修复建议**：数据库侧按 request/turn id 幂等；若先估算再校正，仅记差额，不做第二次全额 consume。

### P2-32 头像/邮件/MCP 及清理队列存在条件性工具风险

见 P2-10、P2-11、P2-18、P2-19；全部依赖 Storage SDK 部分响应、MCP 本地目录权限或工具调用方可信边界，修复前先构造模拟测试确认。

## 三、P3 优化/体验建议（未宣称为安全漏洞）

1. **SSE 共用实现**：主 AI、深研与 Code 工作台解析器漂移；共用 LF/CRLF/EOF/error/abort 语义并覆盖多 chunk 分隔。
2. **大列表分页**：Feed、管理评论/点赞、DM 历史统一 cursor，不以客户端一次载入后切片代替分页。
3. **多实例状态外置**：请求限流、图片字节配额、provider/cache/job 锁按部署规模评估共享存储。
4. **DB 迁移集成门禁**：临时 Postgres/Supabase 每次从空库回放全部 migrations，再跑角色级 RLS/GRANT 正反测试。
5. **合规/发布证据**：migration ledger、数据 TTL、用户删除验收、依赖扫描与构建版本 ID 作为发布清单。
6. **无障碍**：键盘操作、ARIA 状态、对话框焦点陷阱、触控目标和 reduced-motion 自动化检查。
7. **遥测数据最小化**：即便保留同意后行为指标，也不要存控件文本/placeholder；首选匿名聚合指标。
8. **日志/审计**：管理类写接口统一结构化、脱敏、持久化审计；不记录用户正文、模型密钥或可重放 token。
9. **静态产物纪律**：CI 继续 build + consistency；新增 HTML/JS/CSS source map / fingerprint 和关键页面运行 smoke。
