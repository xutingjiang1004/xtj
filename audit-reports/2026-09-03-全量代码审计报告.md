> 审计日期：2026-09-03
> 审计方式：11 个并行审计单元（10 个 agent + 主控直审），只读、未改任何代码
> 覆盖范围：`render-api/`（server.js 21863 行 + 18 个子模块）、`js/` 前端全部源文件、`supabase/migrations/` 58 个 SQL、`tests/` 71 个测试、`scripts/`、部署配置

## 一、审计结论速览

| 统计 | 数量 |
|---|---|
| S 级（严重，可被外部利用 / 数据丢失 / 功能完全失效） | **10** |
| M 级（中等，功能错误 / 越权 / 健壮性缺陷） | **60** |
| L 级（较低，死代码 / 冗余 / 加固项） | **80+** |
| 其中「历史窗口、已修复需核对生产」 | 2（SQL） |

**核心判断**：本项目安全工程水准显著高于同类社区/照片墙平台。RLS、Token 体系、SSRF 防护、输入转义、配额管理均成体系，未发现「注册即可提权 / 任意 IDOR 越权 / 明文密钥硬编码」这类基础漏洞。**真正的风险集中在三处**：① AI 成本与配额的「计量缺失/绕过」（断开免单、搜索不落账、输入低计量）；② 前端渲染链路的 XSS 纵深不足（markdown 正则 sanitize 兜底）；③ 隐私采集合规（无用户同意机制）。

## 五、分模块结论

| 模块 | 结论 |
|---|---|
| server.js（1-6000 配置/AI/安全检测） | 工程水准高（pgrstQuote/双层限流/CAS 状态机/SSRF 防护齐全）；唯一 S 是 rateLimitStore 驱逐策略（S1，修复引入的新问题）；M 集中在"两处实现语义不一致"与"配额账目边界错误" |
| server.js（6000-12000 认证/核心 API） | 未发现裸 IDOR，Token 体系健全（HMAC+timingSafeEqual+吊销）；风险在"降级路径"（pin 误判、delete 缺白名单）与运维侧（吊销集合只增不减、登录接受裸 sha256） |
| server.js（12000-17000 AI/管理） | 最需立改：aborted 免单（S2）+ login-event 灌库（S3）；AI 侧"重功能轻闸门"；管理员平面缺统一 securityRateLimit+审计基线 |
| server.js（17000-21863 流式/Code AI/启动） | 最致命是"静默失效"（flushHeaders 缺失致功能不可用 S4）+ 计量缺失（S5/S6/S7）；权限面干净；全局错误处理被自身防抖废掉（M39/M40） |
| render-api 子模块 | 质量高：web-fetch/provider-registry 的 SSRF 防护完整（DNS pin + 内网段覆盖 + 重定向逐个校验），密钥 AES-256-GCM 存储，PDF 解析有 zip-bomb 防护；残余为 quota TOCTOU（依赖 DB 原子性）+ CSP unsafe-inline |
| 前端 core-parts | 安全基线扎实（token 仅内存、escapeHtml 全覆盖、竞态代次号）；核心风险是"前端越权 UI"（M43），需后端兜底 |
| ai-agent.js | 无 S 级；XSS/SSE/并发逻辑质量高 |
| admin.js | XSS 防护基本到位；最大隐患是管理员 token 可逆混淆存 sessionStorage（真正防线是 httpOnly Cookie）；缓存失效是正确性重灾区 |
| code-workbench + login-device | code-workbench 的 XSS→密钥泄露链是前端最需优先修复项；login-device 合规风险集中在"无同意 + 过度采集" |
| ai-core + photo-wall | markdown-renderer 块级标签短路透传（M58）是核心 XSS 面；两个真实 SSE 尾截断缺陷影响两处复用方 |
| supabase/migrations | RLS 最终态达标；两个历史 S 已修复需核对生产；残余风险在"身份判定依赖 JWT 声明"与 001 快照类型不一致 |
| tests/scripts/配置 | 测试质量高、无真实凭据；vercel CSP unsafe-inline 与 playwright 真实 key 风险最需优先 |
