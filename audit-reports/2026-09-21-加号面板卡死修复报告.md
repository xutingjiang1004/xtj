# + 号面板卡死修复报告（2026-09-21）

## 问题现象

用户截图实证：点击小猫AI 输入栏的 **`+`（更多选项）** 按钮后，面板**卡在左下角**
呈现为一块极小的页面（内容整体缩到约 14% 大小），且**无法正常打开和关闭**。

## 根因分析

放大用户截图后确认：卡死形态的内容就是 `+` 面板本身（额度卡 / 开通 Pro /
上传文件 / 选择文件夹 / 模型 / 思考 / 工作模式 / 网页搜索 全部可见），
判断为面板停在 `transform: scale(0.14)` 的**缩放中间态**。

定位到 `js/ai-agent.js` 的 `openPanel()` 存在两个叠加缺陷：

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | `panelShell.classList.add('open')` 被放进 `requestAnimationFrame` 回调延迟补加 | rAF 被浏览器节流/延迟时（切窗口、GPU 忙、原生 select 弹层阻塞渲染循环）`.open` 迟迟不加，面板停在 `is-opening`（`opacity:0`）**不可见**；用户再点 `+` 又被 `panelOpen=true` 守卫挡住 → **表现为点了没反应** |
| 2 | 视觉补间使用 `transform` **transition** | transition 被中断时，部分环境会把元素冻结在 `scale(0.14)` 的中间帧 → **表现为左下角一小块可见页面**（正是用户截图形态） |

两个缺陷叠加，形成了用户看到的「打不开也关不上、还残留一个小页面」。

## 修复方案

核心思路：**让面板状态收敛从「过渡驱动」改为「时间驱动 + 声明值锁定」**，
从机制上杜绝停留在中间态的可能。

### 1. JS：移除 rAF 延迟，reflow 后同步加类

```js
// 旧：rAF 回调里补加，rAF 被节流即永久不可见
void panelShell.offsetWidth;
requestAnimationFrame(function() {
  if (!panelOpen) return;
  panelShell.classList.add('open');
});

// 新：reflow 保证动画起点，随后同步加类
void panelShell.offsetWidth; // 强制 reflow，保证动画从关闭态起算
panelShell.classList.add('open');
```

### 2. CSS：`.open` / `.is-closing` 改用 keyframes + `both` 填充

```css
.ai-plus-panel-shell.open {
  opacity: 1;
  visibility: visible;
  pointer-events: auto;
  transform: scale(1) translateY(0);
  animation: aiPlusPanelOpen 340ms cubic-bezier(0.32, 0.72, 0, 1) both;
}
@keyframes aiPlusPanelOpen {
  from { opacity: 0; transform: scale(0.14) translateY(10px); }
  to   { opacity: 1; transform: scale(1) translateY(0); }
}
```

关键点：`animation-fill-mode: both` 让终态**锁定在关键帧声明值**。
即使动画被浏览器中断/冻结，元素也停在 `scale(1)` 可见态，
不可能再出现「冻结在 14% 缩放」的画面。关闭同理（终态 = 基础隐藏态）。

### 3. 清理兜底

`S._panelCleanup` 除原有的 abort + 清 timer，新增视觉类复位，
杜绝任何路径残留 `is-opening` / `is-closing` / `open` 导致面板以错误形态出现：

```js
panelShell.classList.remove('is-opening', 'is-closing', 'open');
plusBtn.classList.remove('active');
plusWrap.classList.remove('is-open');
plusBtn.setAttribute('aria-expanded', 'false');
```

### 4. 无障碍降级

`prefers-reduced-motion: reduce` 块补上 `animation-duration: 0.01ms !important`，
确保减动效偏好下动画即时完成（而非残留）。
