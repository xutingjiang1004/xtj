## 二、各问题的修复细节

### 问题 1：上下文丢失（最严重）

```js
// 修复前 —— 致命的静默失败
var r = await supabase.from('posts').select(...).eq(...);
msgRows = r.data;              // 从不检查 r.error
if (Array.isArray(msgRows)) {  // r.data 为 null → 整段跳过 → history 保持 []
```

**修复**：补错误日志 + 安全的空值兜底 + 统一诊断日志。

```js
if (r && r.error) {
  console.error('[AGENT-CHAT] loadAiContext query error (conv branch):',
    (r.error && r.error.message) || String(r.error), '| user=', userName, '| conv=', convId);
}
msgRows = (r && r.error) ? [] : (r ? r.data : []);
```

并在函数末尾输出 `[AGENT-CHAT] ctx loaded: user=.. conv=.. history=N`，下次复现可 30 秒内定位是"读库报错"、"convId 不匹配"还是"确实无历史"。

### 问题 2：工具动画残留

**修复三层**：

1. `settleSearchStatus` 改用 `querySelectorAll` 遍历**全部**状态条（原来只收敛第一个，多容器时其余永久 running）。
2. 早退条件修正：`is-settled && !is-running` 才跳过（原逻辑只要 `is-settled` 就跳过，导致残留 running 无法清理）。
3. **核心**：在 `tool_result` / `tool_error` 到达时**立即收敛**——不等 `done`：

```js
try { settleSearchStatus(assistantNode, { doneText: '联网完成' }); } catch (e) {}
try {
  var _runSteps = assistantNode.querySelectorAll('.ai-tool-step.is-running');
  for (var _rsi = 0; _rsi < _runSteps.length; _rsi++) { /* 置为 is-done */ }
} catch (e) {}
```

### 问题 3 + 4：第三方模型工具能力（最大改动）

**3) 放开工具集**——工作模式下与官方链路对齐：

```js
var customWorkMode = body.work_mode === true;   // 此前全文零引用
function buildCustomTools() {
  if (customWorkMode) return aiToolsForWorkMode();  // 全量 35 个
  /* 非工作模式保留 9 个白名单 */
}
var TOOL_ROUNDS_MAX = 10;  // 原为 6
```

**4) 新增模块级 DSML 解析器** `parseDsmlToolCallsGlobal(rawText, roundNumber, toolsList)`：

支持三种文本协议形式：
- `<tool_calls><invoke name="x"><parameter name="y">v</parameter></invoke></tool_calls>`（用户截图的真实格式）
- `<|DSML|invoke ...>` / `<| | DSML | | invoke ...>` / `<｜DSML｜invoke ...>`（DSML 各变体）
- 裸 JSON `{"tool_calls":[{"function":{"name":"x","arguments":{...}}}]}`

解析成功后产出的结构与原生 `tool_calls` **完全一致**，走同一执行路径；协议外的可见文本单独保留，**原始 XML 绝不再漏进正文**。

安全校验完整：工具名必须在已下发列表内、必填参数校验、类型校验、路径穿越防护。

**测试结果**（8/8 通过）：

| 用例 | 结果 |
|---|---|
| 用户截图的真实格式 | ✅ 解析出 `search_social(platform=douyin, query=徐旭泽)` |
| DSML 标准变体 | ✅ 解析出 `get_weather(city=福州)` |
| DSML 带空格变体 | ✅ 解析出 `read_web_page(url=...)` |
| 裸 JSON | ✅ 解析出 `get_weather(city=北京)` |
| 正常正文（不误伤） | ✅ `detected=false` |
| 缺少必填参数 | ✅ 拒绝：`missing required parameter: city` |
| 未下发的工具 | ✅ 拒绝：`unsupported tool: hack_system` |
| 正文+协议混合 | ✅ 只提取协议，保留正文"好的，我来搜索一下。" |

### 问题 5：内置模型失败

```js
if (!available || !available.size) {
  var envModel = normalizeDeepSeekModelName(process.env.DEEPSEEK_MODEL || '');
  if (envModel && envModel !== normalized) return envModel;
  return normalized;
```

**注意**：此项为防御性修复。若线上仍失败，请查看 `/api/.../ai-config` 的模型探测快照（`status: ready/skipped/error`），确认 `DEEPSEEK_API_KEY` 是否配置、上游 `/models` 实际返回的模型 ID。

### 问题 6：中断误报

```js
// fetchErr 分支
if (doneReceived) {
  // 已完成：静默收尾，不加任何中断提示
  if (!_finalized && aiContent) finishAiMessage(assistantNode, aiContent, aiReasoning, null);
  resetSendingIfCurrent();

```

同时 SSE `error` 事件分支也加同样保护，且 `interrupted` 与 `complete` 交叉校验：

```js
var streamInterrupted = evt.interrupted === true && evt.complete !== true;
```

### 问题 7：下载失效

新增 `triggerFileDownload(href, filename)`：把 `data:` URL 解码为 `Uint8Array` → `Blob` → `URL.createObjectURL` → 同源 `blob:` URL 触发下载，30 秒后 `revokeObjectURL`。

`buildDownloadLink()` 统一封装，三处下载卡片（`generate_pdf` / `make_file` / 图片）全部改用。非 `data:` URL 保持浏览器原生行为。

### 问题 8：复制浮层错位

```js
// 定位加上界约束
var maxTop = window.innerHeight - menuRect.height - 8;
top = Math.min(Math.max(8, top), Math.max(8, maxTop));
// 滚动 / resize / visualViewport 变化即关闭
window.addEventListener('scroll', _onMenuViewportChange, { signal: _menuSig, passive: true, capture: true });
window.addEventListener('resize', _onMenuViewportChange, { signal: _menuSig, passive: true });
```

### 问题 9：操作按钮消失

`clearAssistantTransientStatus` 的策略从**删除**改为**收敛**：

| 容器类型 | 修复前 | 修复后 |
|---|---|---|
| 含 `.ai-tool-result-card` 或 `.ai-tool-step` | `remove()`（连带删掉工具时间线） | `is-settled` 保留 |
| 纯占位空壳 | `remove()` | `display:none` 隐藏（不破坏 DOM 引用） |

并在 `finishAiMessage` 末尾加**强制兜底**：校验 `.ai-msg-actions` 是否存在且已连接，缺失则重新挂载。
