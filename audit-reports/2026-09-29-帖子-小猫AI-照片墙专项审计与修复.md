# 帖子、小猫 AI 与照片墙专项审计及修复

日期：2026-09-29  
分支：`main`  
范围：单页前端的帖子发布与动态内容、小猫 AI 对话、照片墙展示和上传，以及这些功能直接依赖的后端接口、构建与测试。

## 审计方式

逐一追踪页面入口、懒加载、状态更新、请求与回包、后端持久化和构建产物；结合现有合同测试、运行时模拟及边界用例复现。严重度按用户影响和数据风险分级。这里记录已确认并已在本次修复的问题，不把未经复现的猜测列为缺陷。

## 已确认问题与处理

| 模块 | 严重度 | 问题和影响 | 修复位置 |
| --- | --- | --- | --- |
| 帖子发布 | 中 | 发布入口允许的文件类型与上传处理能力不一致，音频无法从选择器选取。 | `index.html` |
| 帖子及通用文案 | 中 | 动态加入的乱码文案未被修正；扫描可能改写代码、模板或输入区域的原文，并可能反复触发自身观察器。 | `js/features.js` |
| 帖子与照片墙上传入口 | 中 | 首次点击在模块懒加载后重放文件选择器动作，浏览器可能拦截失去用户手势的弹窗。 | `js/core-parts/01-bootstrap.js` |
| 小猫 AI | 高 | 非流式响应头已到达后过早解除超时与取消绑定，响应体挂起时请求可无限等待。 | `js/ai-agent.js` |
| 小猫 AI | 高 | 本地历史缓存可能保存附件 data URL，造成存储膨胀和敏感内容持久化；历史加载失败可能清掉界面上仍可见的消息。 | `js/ai-agent.js` |
| 小猫 AI | 高 | 继续对话时当前消息与历史边界不明确，历史附件和图片上下文丢失；自定义模型会覆写上一轮用户消息。 | `js/ai-agent.js`、`render-api/server.js` |
| 小猫 AI 后端 | 中 | 非视觉模型不能收到历史图片，却跳过了图片 OCR；历史附件只按单条限量，缺少跨轮总数约束。 | `render-api/server.js` |
| 小猫 AI | 高 | 本地待同步消息和远端历史合并缺少逐条匹配，可能重复显示或丢掉尚未保存的轮次；深度思考与普通发送共用状态以及关闭面板后的异步回调存在竞态。 | `js/ai-agent.js` |
| 小猫 AI 后端 | 高 | 全局 JSON body 限额与 AI 附件路由需求冲突；扩大全局限额又会使未认证路由承受过大请求。 | `render-api/server.js` |
| 照片墙 | 高 | 单次 DOM 渲染上限 500 张后缺少稳定翻页路径，更多照片虽已加载却无法继续浏览；边界页和无观察器环境会卡住。 | `js/photo-wall/render.js`、`css/style.css` |
| 照片墙上传 | 中 | 取消批量上传后使用计划总数报告为已处理数，甚至把全取消显示为成功。 | `js/photo-wall/upload-ui.js` |
| 照片记录清理 | 高 | 只在帖子内容中查找存储路径引用，漏掉旧帖 `media_url` 引用，可能误删仍被引用的文件。 | `render-api/photo-create.js` |
| 构建与持续集成 | 中 | npm 测试引用了错误的服务端测试路径；UI 测试未先生成前端资产。 | `package.json`、`.github/workflows/ci.yml` |

## 验证

`npm run build` 成功；`npm run test:consistency` 的错误与警告均为 0；`npm run test:syntax` 通过；`npm test` 的 Node 测试 **809/809**、沙箱合同 **49/49**、完整静态守卫 **99/99** 通过；`git diff --check` 通过。新增运行时用例覆盖照片墙 500/501/1001 边界、相册与键盘加载、上传并发取消、帖子文案扫描、AI 响应体超时、历史消息对账，以及视觉/非视觉模型的历史附件处理与总量预算。

本地 `npm run test:ui:critical` 因环境未安装 Playwright 的 Edge 浏览器，两个用例在启动浏览器前停止；CI 的 UI 作业按配置安装 Chromium，并在本次修复后先构建前端资产。此次无法将本地浏览器用例计为通过。

## 边界

运行时与合同测试覆盖本次已确认的主要边界。深度思考关闭期间的 token/锁隔离由静态合同和历史合并运行时用例共同验证，尚无完整 fake-fetch 浏览器竞态模拟。外部 AI 提供商、生产数据库、真实用户数据及浏览器权限仍受环境配置约束；未对生产数据作直接修改。
