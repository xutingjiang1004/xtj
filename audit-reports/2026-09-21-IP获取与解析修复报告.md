# IP 获取与解析修复报告

- **日期**：2026-09-21
- **基线**：`c5c7a73`
- **现象**：帖子"IP属地：未知"；管理端用户详情最近IP为 `10.193.27.131`，点"重新解析IP"报"IP 地区解析失败（所有数据源均不可用）"

---

## 根因

**入库的 IP 本身就是错的。** `10.193.27.131` 是 10/8 私有网段地址——Render 边缘到应用之间实际存在多层内网代理，而 `server.js` 只配置了：

```js
app.set('trust proxy', 1);   // 只信任一跳
```

`getClientIp()` 又只信 `req.ip`（Express 按 trust proxy 解析 X-Forwarded-For）。信任一跳不够 → `req.ip` 仍是 Render 内网地址 → 私有 IP 直接写进登录事件与 `last_ip` → 私有 IP 送给任何地理数据源都必然失败。

即：**不是"数据源不可用"，是"IP 本身不可解析"**，报错文案误导了排查方向。解析侧的防御（`isPrivateOrReservedIp` 前置拦截、Nominatim UA/429 退避）此前均已就位，全部失败都是"正确地失败"。

## 修复内容（render-api/server.js）

| # | 修复 | 说明 |
|---|---|---|
| A | `trust proxy` 改为 `['loopback', 'linklocal', 'uniquelocal', '100.64.0.0/10']` | 信任全部私有/保留网段。Express 从 X-Forwarded-For **从右往左**跳过所有受信代理地址，`req.ip` = 第一个公网地址 = 真实客户端。**安全性不变**：客户端伪造的 XFF 值只会出现在链最左侧，从右往左扫描永远不会选中它 |
| B | `getClientIp` 增加私网跳过 + XFF 兜底 | 先取 `req.ip`/socket，但**跳过私有地址**；若全是私网（代理层数再超预期），从 XFF 链右往左找第一个公网 IP；最终兜底返回原始 `req.ip` 保证日志可溯源 |
| C | 管理端 `/admin/user/resolve-ip` 对私网 IP 返回 `422 private_ip` | 明确告知"该 IP 是内网/保留地址，无法解析属地（历史缺陷数据）"，不再误报"所有数据源均不可用" |
| D | `retryIpRegionAsync` 对私网 IP 直接 `setIpRegionFailed('private_ip_unresolvable')` | 不再安排 30s/5min 两次注定无效的重试 |

新增合约测试 `tests/client-ip-resolution-contract.test.js`（6 项），覆盖：trust proxy 配置断言、私网判定行为、XFF 右往左取公网（含伪造忽略）、源头拦截、端点错误码、重试跳过。

## 验证

- Express 真实行为验证（本地起 app 模拟 Render 多跳）：
  - `XFF: "223.104.55.10, 10.193.27.131"` → `req.ip = 223.104.55.10` ✅
  - `XFF: "6.6.6.6, 223.104.55.10, 10.193.27.131"`（客户端伪造在最左）→ `223.104.55.10` ✅ 伪造被忽略
  - `XFF: "10.5.5.5, 192.168.1.1"`（全私有）→ 保留原始值可溯源 ✅
- 全量测试：`node --test tests/*.test.js` **593 pass / 0 fail**（含新加 6 项）+ `complete-tests.js` **99 pass / 0 fail**

## 遗留说明

1. **存量脏数据不可修复**：已写入的 `10.193.27.131` 等私有 IP 无法重新解析（真实公网 IP 在当时就已丢失）。该用户下次登录/访问后，登录事件会记录正确的公网 IP，属地自动恢复。
2. 截图一中"认证服务暂时不可用 / 消息列表刷新失败 / 地址解析失败（添加位置）"三个 toast 出现在同一时刻，为 Render 冷启动/网络抖动期的群体性失败，非本缺陷衍生；其中逆地理编码（Nominatim）已带 UA 与 429 退避，观察即可。
3. `ipwho.is` / `ipapi.co` / `ip-api.com` 免费额度有限（ip-api.com 45 req/min），后续若用户量上涨可考虑自托管 mmdb 本地库，零外呼零配额。
